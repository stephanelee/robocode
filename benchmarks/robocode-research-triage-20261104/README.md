# Post-Peak research triage: no new experiment authorized

2026-11-04. These source/document audits preserve decisions made after the valid
25-round MeridianPeak rejection. **Zero new physical rounds, tests, fits, parameter
sweeps or controller replays were performed for this triage.** No new bot or gameplay
implementation exists here. The archived Branch document is an **unregistered,
deferred draft**; none of its proposed45/180/225-round budgets were opened. It is not
an active protocol, implementation instruction or clearance to run games.

## Decisions

1. Defer the continuation-planner draft. Issue84/PR85 already tested the central
   receding two-wave continuation hypothesis and failed20 valid rounds. The exact
   proposed four-plan/strict-clear/Peak implementation differs, but no evidence
   isolates those changes as helpful. Its former motivation omitted direct prior
   art. [Implementation addendum](branch-prior-art-addendum.md) and
   [independent correction](branch-independent-prior-art.md) supersede that claim.
2. Reject a generic common-cohort GF/four-expert selection proposal as a new
   mechanism. PR64 already implemented it and failed its valid20-round pilot;
   PR65's later integrity failure is separately invalid, not another valid test.
   [Full Meridian inventory](gun-inventory.md) and
   [independent prior-art/evidence review](gun-independent-prior-art.md) preserve
   the distinction. Current Peak journals do not directly prove a joined ex-ante
   four-expert cohort; no retrospective fit or reconstruction was performed.
3. An ordered-prefix/complete historical-continuation predictor appears untested
   in the inspected own bots. Adaptive Prime already replays historical paths;
   generic history retrieval is established prior art. The narrow distinction and
   severe availability/physical-mapping limits are in [the inventory](sequence-prior-art.md).
   This is a possible research question, not a selected model or authorized study.
4. [Pinned Diamond Port source audit](diamond-port-source-audit.md) identifies a
   precise STOP forecasting discrepancy after composing adapter, actual Python SDK
   and engine. Motion order/wall predictions were already documented. No executed
   Diamond-fork repair was found. [Independent SDK/engine review](diamond-stop-independent.md)
   confirms the narrow source mismatch and the required STOP-purpose seam. A separate prospective, independently reviewed
   zero-game composition diagnostic is being considered. No cases were evaluated,
   no fork was implemented, and no competitive benefit is claimed.
