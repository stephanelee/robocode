# Independent SDK lifecycle and observer/private cohort audit

Reviewed before MeridianPeak's source/JAR/benchmark freeze and before any games. This is source evidence and a contract recommendation, not a measured explanation of an earlier invalid experiment. No game, server, matrix or live opponent was run for this audit.

Pinned engine/API source: `robocode-dev/tank-royale` commit `c8ad3a8d19a843f6258d6f6f9db7f29229963903`, Java Bot API 1.4.0. The repository's prior [closed-round repair](../../../docs/improvements/challenger-round-lifecycle.md) documents the same ordering. Sources were independently fetched from the pinned official GitHub tree during this review.

## Supported lifecycle boundary

- [WebSocketHandler](https://github.com/robocode-dev/tank-royale/blob/c8ad3a8d19a843f6258d6f6f9db7f29229963903/bot-api/java/src/main/java/dev/robocode/tankroyale/botapi/internal/WebSocketHandler.java), `handleRoundEnded`: public `onRoundEnded` executes first; internal round-end handlers then stop/invalidate the bot thread; `flushFinalTurnEvents` drains remaining queued events. Immediate final serialization in the public round-end callback can precede legitimate terminal shots, hits, scans and learning mutations.
- The same class's `handleRoundStarted` publishes internal handlers before the public callback. [BotInternals](https://github.com/robocode-dev/tank-royale/blob/c8ad3a8d19a843f6258d6f6f9db7f29229963903/bot-api/java/src/main/java/dev/robocode/tankroyale/botapi/internal/BotInternals.java) stops/invalidate-owns the old thread at priority 110, clears the old tick/event queue via BaseBotInternals at 100, and starts the replacement waiting for its first tick at 90. Thus the public round-start callback is a place to seal the already drained previous completed round before resetting/reopening.
- `handleGameEnded` calls the public callback before its own internal stop and final flush. Final sealing there relies on the preceding ordered RoundEnded drain; do not claim that GameEnded's public callback is intrinsically after every possible flush. Require a pending completed RoundEnded before sealing. Abort/disconnect without it must not fabricate completion.
- [EventQueue](https://github.com/robocode-dev/tank-royale/blob/c8ad3a8d19a843f6258d6f6f9db7f29229963903/bot-api/java/src/main/java/dev/robocode/tankroyale/botapi/internal/EventQueue.java) prioritizes critical events, then turn and configured priority; event order need not equal the observer event list. Noncritical events older than two turns can be discarded. Preserve chronological model/accounting contracts rather than assuming callback list identity.

Recommended adapter states: ACTIVE → CLOSING at public RoundEnded → SEALED at the next public RoundStarted or final GameEnded. Accept queued terminal event/model updates while CLOSING, but reject decision-loop/command mutations. Under one adapter monitor, seal row/model exactly once before reset. Duplicate lifecycle callbacks must not increment completed-round counters twice. Once SEALED, do not accept model changes or rewrite a supposedly final endpoint. The launcher must await complete final models/rows after official results before terminating clients.

All callback/model mutations and decision calculations share the adapter monitor. `go()` and SDK waits remain outside it. An adapter round epoch rejects already registered stale run threads after reopening. At run entry, check `Thread.currentThread().isInterrupted()` **inside that same monitor before capturing the epoch**: pinned [BaseBotInternals](https://github.com/robocode-dev/tank-royale/blob/c8ad3a8d19a843f6258d6f6f9db7f29229963903/bot-api/java/src/main/java/dev/robocode/tankroyale/botapi/internal/BaseBotInternals.java) `stopThread` interrupts an old thread, and there is no interrupt-clearing operation between createRunnable's last ownership check and `bot.run()`. The monitor ensures an uninterrupted old entrant captures the old epoch before a new public round-start can advance it, or an interrupted stale entrant is rejected.

Do not call `dispatchEvents` as a new run-entry ownership probe. BaseBotInternals explicitly avoids pre-dispatch before initial setup/go because it changes first-turn callback/intent order. The adapter relies on the SDK's ordered WebSocket dispatch, queue drain, thread invalidation and ordinary interrupt behavior; it is not a guarantee for arbitrary injected stale callbacks, externally cleared interrupts or a modified SDK.

## Observer and private accounting

[TurnProcessor](https://github.com/robocode-dev/tank-royale/blob/c8ad3a8d19a843f6258d6f6f9db7f29229963903/server/src/main/kotlin/dev/robocode/tankroyale/server/core/TurnProcessor.kt) fires guns, moves bots, checks scans and bullet contacts, then computes round outcome. It copies bot snapshots before emitting death events and removing dead bots from the next turn. Consequently a bot that dies on a tick still has a bot-state snapshot on that tick. Its same-tick confirmed shots and hit events belong to the deliverable private cohort and must survive the final drain. **Do not filter this cohort by positive energy or by being alive at tick end.**

[TurnToTickEventForBotMapper](https://github.com/robocode-dev/tank-royale/blob/c8ad3a8d19a843f6258d6f6f9db7f29229963903/server/src/main/kotlin/dev/robocode/tankroyale/server/mapper/TurnToTickEventForBotMapper.kt) returns no private tick when that bot is absent from the turn snapshot. The engine can retain bullets owned by a removed bot, so a later observer-only outgoing hit is a legitimate generic source possibility; there is then no private callback to reconcile. However the same pinned TurnProcessor ends a normal **1v1 round immediately when the alive bot/team count is at most one**, regardless of bullets still flying. Therefore this is not a claim that later posthumous ticks normally occur in this experiment's 1v1 roster. The distinction must remain explicit rather than being used to excuse missing same-tick callbacks.

Source-faithful reconciliation:

1. Retain all official observer shots/hits/damage/energy for competitive metrics. None is removed from the score comparison.
2. Reconcile private confirmed own shots and shot energy to all observer own creations; own state exists when firing occurs, including a same-tick death.
3. Reconcile private outgoing hits/damage to observer own-bullet hits on ticks containing the own bot-state snapshot. Separately retain/count any observer-only outgoing hits/damage on ticks without it. Do not infer callback availability merely from the DeathEvent or the owner's final energy.
4. Reconcile incoming hit counts/damage on deliverable own-state ticks; simultaneous terminal hits are still part of that tick's cohort. [EventMapper](https://github.com/robocode-dev/tank-royale/blob/c8ad3a8d19a843f6258d6f6f9db7f29229963903/bot-api/java/src/main/java/dev/robocode/tankroyale/botapi/mapper/EventMapper.java) maps a private BulletHitBot event to HitByBullet when its victim is the recipient; otherwise to outgoing BulletHitBot. Preserve uncapped event damage, not the capped official damage score.
5. Compare private round/model counters only after final sealing/drain. Missing metadata or a same-tick discrepancy is an invalidity, not an invitation to waive counters after outcomes. Existing original-v3 control markers supply less private evidence; state that limitation explicitly.

## Skip detection and tests before freezing

Immediate private skip-marker polling can abort a running game after detection; observer-only skipped events are validated from the completed official recording before any subsequent game begins. This is the declared detection boundary, not a claimed live observer callback. Retain all physical and partial rounds from an invalid attempt; do not replace them.

Required ordinary contract cases include RoundEnded → terminal callbacks → next RoundStarted and final GameEnded; no snapshot/counter advances at the early end callback; final models include late labels/shots; exactly-once completed rounds; duplicate end/seal; abrupt GameEnded without prior completed end; stale registered run epochs; interrupted stale run entry; callback access while `go()` waits; same-tick death/fire/hit reconciliation; and a synthetic absent-owner observer-only outgoing hit classified separately without changing competitive totals. These fixtures establish contracts only. No competitive improvement follows from passing them.
