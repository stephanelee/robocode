## Hypothesis and permitted treatment

It does not predict a general strength gain or a Diamond damage-exchange improvement. Independent source-only audit `c067595c034624312a34fd3e2b2491afccfd176a9b5101c12731c0d277a1f9cb` and the 16-file official chronology manifest are retained as companions. These historical contacts motivate a Retcon bookkeeping experiment; they do not establish eligible-scan corrections, phantom-wave frequency, harm or future competitive benefit. ## Exact observation and cleanup contract

Use a separate constant-space SAME-TURN ram accumulator, logically `(ramTurn, ramEventCount, ramCorrection)`. Original bullet correction map and cleanup retain their existing eventT→scanT+1 semantics. A HitBot event at T with T later than the last accepted scan accumulates exactly−0.6 and one event for T; a later event turn replaces/discards an older unconsumed ram bucket. Same-turn legitimate events sum once per delivered callback. An event at or before the already accepted scan turn cannot retroactively alter inference and is discarded from the correction bucket; it is still counted in raw-event telemetry. Never change SDK priorities. The default legal ordering makes same-turn HitBot available before its scan; stale/late delivery is a tested safety case, not a second application.

On the first accepted scan T (`T > scanT`, as original), snapshot the ram bucket only if `ramTurn == T`, then consume/discard any ram bucket with `ramTurn <= T` EXACTLY ONCE, whether or not inference is eligible. If original consecutive-history condition `ePrev != null && ePrevT == T−1` holds, add this snapshot to the original `corrections[T−1]` plus unchanged wall correction in the existing power calculation. If that condition is false, discard the ram snapshot without inference; do not carry it into a later scan. Keep original shot eligibility `0.0999 <= inferredPower <= 3.0001` and all following target-history/feature checks unchanged. Duplicate/stale scans retain original early return, do not reconsume or advance models, and cannot create another wave. All ram bucket state and counters reset at RoundStarted. Round numbers/turns do not leak across games. Multiple legitimate bullet corrections continue to sum in their existing map and can combine with SAME-TURN ram in the same accepted scan. Do not invent duplicate collision events from duplicated scan delivery.

Required source-derived pure fixtures must exercise the production event/inference boundary actually called by the candidate and demonstrate frozen-original contrast, rather than merely testing a copied arithmetic helper: RAM alone at T; RAM plus legal shot p0.1/1.2/3 at T; real0.6 shot at T+1; post-scan bullet damage and enemy hit bonus at T consumed only at T+1, including combination with ramT; both isRammed values; reset; missing/nonconsecutive scans; duplicate/stale scans; stale/late ram delivery; multiple legitimate corrections. Fixtures may use a narrow test seam reviewed for no gameplay behavior; they run no bot/server/game or alternate physics. They establish semantics only.

## Fixed diagnostic scope and exposure gate

Both arms retain complete start/stats/end, own skip and integer maxMs records per round. Candidate emits five additional round-local integer aggregate counters, baseline values explicitly N/A:

- `rawRamEvents`: delivered own HitBot callbacks in that round, including callbacks discarded as stale/late.
- `eligibleRamCorrectedScans`: accepted scans entering the ORIGINAL consecutive-enemy-history power-computation branch whose consumed SAME-TURN ram snapshot contains at least one event. Count one per scan, even if the corrected inferred power is outside the firing window or subsequent own-target history is unavailable.
- `eligibleRamCorrectionEvents`: sum of event counts in those eligible snapshots.
- `ramChangedPowerScans`: eligible corrected scans for which adding the nonzero ram scalar changes the scalar inferred power versus the same scan calculation with that current ram scalar omitted.
- `ramChangedGateScans`: eligible corrected scans for which the unchanged [0.0999,3.0001] gate differs between those two scalar powers.

The two comparisons are O(1), side-effect-free scalar diagnostics. They do NOT simulate legacy Keel's delayed correction, create counterfactual waves, run a second search, change commands, touch models or feed any policy. They measure current-correction activation, not historical-baseline causal effect. All five counters use checked round-local long integers, cap at1,000,000 per counter per round. First attempted increment above cap sets a one-time private `diagnosticOverflow` fault marker; no wrap or silent saturation is accepted, and the controller stops at that first integrity fault. Normal telemetry adds at most five integers to the existing one stats record per round; no per-tick traces or outcome-selected diagnostics. The constant-space bucket and counters reset each round, not learned models. In complete normal rounds require `0 <= ramChangedGateScans <= ramChangedPowerScans <= eligibleRamCorrectedScans <= eligibleRamCorrectionEvents <= rawRamEvents`; baseline diagnostics remain N/A. Review counters against actual own legal contact events/source wiring; counts are source/runtime-bound telemetry, not a claim that an independent full private callback trace exists.

Each stage independently requires candidate Retcon sum(`eligibleRamCorrectedScans`) >0, over ALL of that stage's candidate-Retcon games only: two10-round screen games or three10-round confirmation games. No screen/history/other-opponent/baseline counter can satisfy confirmation exposure. Raw contacts alone do not satisfy it; changed-power/gate/wave count is NOT an additional exposure threshold. Report all counts, including zero gate changes. With no eligible candidate Retcon exposure, a fully acquired stage is INCONCLUSIVE: no confirmation/promotion, retain all score-gate outcomes and no replacement games. This classification is not a competitive failure attributable to the repair. Integrity-invalid takes precedence; with exposure>0, any score gate failure is REJECT. Do not condition, filter, extend or stop the fixed games on contacts, exposure or scores.
