## Hypothesis and intervention

The existing bot conflates opponents in a single track, suppresses multiple same-turn scans and applies duel surfing/energy accounting to melee. A dedicated policy while enemyCount > 1 should improve four-bot score share. Track every scanned ID independently; remove dead opponents; sweep radar; select a fresh reachable target with hysteresis; fire bounded circular/linear intercept shots with distance/energy-aware power. Movement searches 64 directions using engine-exact short path prediction, summed opponent proximity/energy/angular risk, wall/collision penalties and recent-position avoidance. No opponent internals, privileged observer input or external models enter gameplay. Constants fixed in the first implementation; no parameter search, score-driven repair or extra games.

Use the original duel policy when enemyCount <= 1. On a melee-to-duel transition, clear transient duel tracks/waves/corrections before accepting the survivor scan; do not feed mixed melee identities into duel learning. Original from-start 1v1 gameplay should retain its code and behavior. Version/description/gameTypes reflect melee support. Fixtures check per-ID simultaneous scans, death/stale filtering, predictive boundary constraints, fire limits, safer movement, and transition reset semantics; fixtures establish correctness only.
