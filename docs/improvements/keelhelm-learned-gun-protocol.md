## Hypothesis and scope

A per-opponent learned displacement forecast can improve melee shots over constant circular prediction while preserving survival and inherited duels. Learn only actual legal scan endpoint pairs. No observer data, prerecorded training or opponent internals enter the bot. Movement, radar, target selection, power, firing tolerance/energy gates and melee-to-duel reset remain unchanged. Earlier rejected gun selector/power/movement/radar/obstruction/transfer policies stay excluded. The circular gun remains the fallback; this is one motion model with data-confidence guards, not virtual-gun winner selection.

The four-game snapshot in PR128 motivated this hypothesis: during the melee request phase KeelHelm fired5,216shots/807recorded hits at meanpower1.081; Prism4,929/899 at1.536. Phase is determined from the shooter's preceding tick (the request state), and hits are linked by round/owner/bulletID. These read-only counts consume zero new games and are descriptive; unresolved/censored rounds and uncontrolled starts prevent treating ratios as calibrated probabilities or causal evidence. They are not training data for the candidate.

## Fixed learned model

Separate storage per opponent ID, cold process per game. Models persist across rounds within that game; observation histories, pending shots, dead-ID state and caches clear each round and at the duel transition. Death clears that ID's transient observations/cache; no cross-ID or cross-round endpoint pair is formed. Only scans while enemyCount>1 train the model. At most16 recent observations/ID and1024 samples/ID (FIFO ring). Candidate runtime has no disk/model loading.

An observation has position, body heading, signed speed, scan turn, own position, arena size, observed angular rate and speed acceleration. Angular rate=wrapped heading difference/scan gap clipped±10deg; acceleration=(current speed−previous speed)/gap clipped±2. Context is known only after two scans separated by1..12turns. Retain histories up to99turns. For each new observation choose the closest prior actual observation for each desired elapsed horizon8,16,24,32,48,64,80,96 (tolerance±3, actual elapsed constrained8..96); ties prefer the more recent anchor. No interpolation or synthetic target positions. Reject nonfinite/unphysical endpoints (displacement>8×elapsed+0.001). Anchor context must be known. Label is forward/lateral displacement in anchor body-heading coordinates divided by8×actual elapsed; thus average velocity components, not endpoint guesses.

Eleven normalized context features: signed speed, angular rate, signed acceleration, own range/1200, elapsed horizon/96, forward/back/left/right ray distances to legal arena bounds divided by400 and capped1, cosine and sine of body heading relative to bearing toward own observed position (mapped0..1). Speed maps−8..8 to0..1, angular rate−10..10, acceleration−2..2. Weights:2,1,1,0.5,3,0.75,0.75,0.75,0.75,1,1 (sum12.5). Weighted squared feature distance divided by12.5.

Query horizon comes from the inherited circular endpoint: scan age + distance(current own position,circular endpoint)/bulletSpeed. Use learned data only for scan age0..12 and total horizon8..96. Require at least128 stored samples. Select up to24 nearest samples from distinct (round,anchorTurn) origins, each with elapsed within12turns of query and normalized squared distance<=0.25; require at least16 distinct origins. Deterministic nearest selection; exact distance ties prefer newer stored sample. Weight each by1/(0.02+distance). Compute weighted mean/variance of both velocity-label components.

Rotate mean velocity back to current observed body heading and apply from the latest actual target position. Refine flight horizon with three fixed cheap endpoint/range iterations using that same mean; clamp endpoints to18px arena bounds. Require final horizon8..96 and within12turns of queried horizon. Reject if uncertainty radius8×finalHorizon×sqrt(varForward+varLateral)>max(36,0.25×current target range). All rejection paths return the inherited circular aim. Cache nearest-neighbor results until a new target scan, power change>0.1 or circular query horizon change>=4turns; never more than1024 samples examined per fresh query. No nearest-neighbor retuning after games.

Register pending metadata only after setFire succeeds; confirm by legal BulletFiredEvent turn and power. Count a materially changed learned shot only if actual confirmation exists and learned/current circular angles differ>0.1degree. Per-round diagnostic counters and per-ID changed-shot counts never feed control. Keep a bounded256-entry confirmed-shot ledger for actual hit, wall, bullet-collision and unresolved/censored observations; eviction/round end/transition cannot be silently treated as misses. These diagnostics prepare later power analysis but do not change power here.

Opponents/runtime remain frozen tournament pins, including official sample transfer guards. Rotate all four melee launch slots twice; alternate arm order by pair. Bot seeds2026112200+pairIndex across the fixed schedule, identical within a pair only for bot choices, not engine placements. No historical pooling, warmup, score-driven stopping or selective replacement. All valid planned games finish.
