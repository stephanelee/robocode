# Confirmed-outcome power candidate 0.6.0

The [prospective protocol](keelhelm-outcome-power-protocol.md) and issue #131 precede source changes. This candidate forks accepted 0.2.1 in `benchmarks/keelhelm-outcome-power/candidate-project`. It includes no learned displacement gun or previously rejected policy. The normal project remains exact accepted 0.2.1.

`MeleeOutcomePower` holds 32 legal resolved shot outcomes per intended target/range-bin, plus a 256-shot confirmed ledger. It applies the registered bounded increase only with sufficient successes, fresh scans, range and reserve. Confirmed shots accumulate all available same-tick terminal callback kinds; a subsequent live tick establishes completed delivery for unsuccessful outcomes, while a positive hit dominates collision/wall callbacks. End-cutoff non-hits and evictions are censored and do not teach the window. Windows persist across rounds within a cold game; no disk model or observer data is read.

Chronological F/R/E telemetry stores actual confirmation, request-context sequence and calibration state, resolution masks/damage and evictions. The acquisition reducer replays bounded windows independently from the bot class, checks every request against its earlier sequence state and fixed rule, matches actual powers/available callback outcomes against original observer events, and reconciles counts. Observer-only later outcomes are not assumed to have reached a dead bot. A separate independent auditor also reviews all raw evidence.

Circular aim, movement, radar, target selection, firing tolerance/energy gates and the duel controller stay inherited. Only melee selected power changes. The outcome ledger advances before either phase branch; transition clears unconfirmed pending state while confirmed shots can legally resolve later. `KEEL_HELM_OUTCOME_POWER` defaults true only in this isolated candidate, false for contracts.

Java 17 offline build: 29 tests pass, zero failures/errors; committed/rebuilt JAR matches across 833 entries, SHA256 `e6227d4b561754f7ef93aceb1411620f77df39bfdda758fb043afdbdaeda004b`. Six new tests cover sample eligibility/FIFO, per-ID/bin/round isolation, multi-outcome hit precedence, cutoff censoring, reserve/kill/stale gates, confirmation and bounded ledger. Four Python contracts verify schedule/budget, gates, multi-outcome chronological replay and rejection of a forged request context. Two initial test-fixture expectations were corrected (a replacement hit had evicted a hit; collision+hit mask is5, not7); the failed log is retained. Fixtures consume zero competitive games and establish no strength.

The fresh driver is `tools/keelhelm_outcome_power.py`: prepare once, independent exact-freeze/roster review, then run once with that approval hash. It retains all recordings, invocations, telemetry and strict resource/cleanup evidence. No score-driven stopping, retry, resume or historical pooling. Evaluation is exactly40 games /520 rounds, serially on minimind using JDK25 and frozen opponents.
