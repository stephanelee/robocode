## Interpretation and acquisition details

The unit of analysis is a complete five-round melee game, paired by a unique fresh geometry and seed. Equal-game score share is own total score divided by all entrants' total score. Survival share uses official survival score divided by all entrants' survival score; a zero denominator yields zero for both arms. The melee effect is the arithmetic mean of the 32 candidate-minus-control shares. The exact test uses 32 unlabelled first-minus-second contrasts and the sealed balanced subset. Report exact fractions, all pair effects, aggregate scores/wins, and all gates even if rejected.

All rosters, placements, orders, seeds and identities are frozen before gameplay. Within each pair positions and seeds are identical between arms. Pair games run consecutively, melee first, then Diamond Port, Retcon, Walls, SpinBot. Native process/HOME reset and full verified cleanup precede the next slot; no continuing entrant memory or tournament state. Fixed IDs are alphabetical as independently audited in A/A. The 100000 microsecond turn deadline, engine heaps/GC and legal sensor events remain unchanged. Resource monitor samples every two seconds; less than 20% available memory or more than 128 swapout pages per sample for three consecutive samples, missing/reset counters, or failed cleanup invalidates the study. Admission is checked per game. The 960-second per-game timeout remains unchanged.

Only melee policy movement is changed. The candidate calls the exact old bit-8 movement algorithm, with other rejected feature bits absent. A shadow parent's command is evaluated at the same actual state with the candidate's destination/history; its difference count measures intervention exposure, not an independent control trajectory or strength. Duels from the start use the unchanged parent logic. Candidate version metadata is 0.7.0; normal KeelHelm remains exact 0.2.1 throughout measurement.

Geometry rejection consumes all coordinates/headings for a complete attempted layout before rejecting it. Python's isolated Random(2026112601) generates these layouts in schedule order; geometry randomness is a reproducibility device, not the assignment mechanism. A single operating-system secrets.randbelow draw selects the balanced treatment assignment. Draw is persisted with exclusive file creation, source hash and timestamp before use; rerunning preparation reuses/verifies this draw, never redraws it. Initial position is held constant across rounds within a game. The randomization test conditions on these fixed layouts and game slots. Native opponent randomness and scan ordering remain unmodified. Its exact interpretation assumes no treatment-driven cross-slot interference; cold processes/admission mitigate but do not establish this assumption. Duel guard thresholds are operational checks, not statistical proof of equivalence.

Record all physical games/rounds including failures. No optional stopping, replacement, or automatic retry. Preserve full recordings, transport audit, telemetry, resource streams, source/JAR/pins, official scores, and independent audit in a durable archive with SHA256. Complete this study only after the improvements ledger includes its decision, measured budget, PR, detailed report and raw evidence links. No result from A/A or previous candidates is part of the new test statistic.
