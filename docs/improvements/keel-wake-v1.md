## Hypothesis and exact treatment

One isolated derivative KeelWake0.1.0 from ORIGINAL Keel0.1.0 at24fb9a5f02065c0bf0b146b8387c2a9d8a272373 (source tree4d76ac190e9d303ce1657cb2c3659961ef72f611, JAR SHA25677b8a5c3114641c12a94f36c83083d27c419416ee691d725fd19f0284a69db6f). Hypothesis: updating selected in-flight-wave danger estimates after a newly matched legal incoming hit/collision label improves Diamond equal-game share and cold-game consistency while preserving Retcon/sample performance and original Keel's fire economics. No isolated component superiority or canonical image claim follows from a screen.

Original Keel computes each wave density once at birth, although later matched HitByBullet and BulletHitBullet events update the danger KNN while other waves may remain in flight (Surfer.java14–25,94–130,196–205,269–307; Keel.java69–77,100). Wake changes ONLY when that existing density estimator is evaluated for an existing wave:

1. Each new wave caches the current hits.seq epoch together with its existing birth density and unchanged fire-time features/origin/power/direct/latDir/fire turn.
2. Each plan call first selects the same w1/w2 using ORIGINAL selection/order. For each distinct selected unpassed wave whose cached epoch differs from current hits.seq, recompute exactly existing density(wave.features), store the new normalized array and epoch BEFORE any first/second-wave path score. At most2 refreshes per plan call; never refresh inside path/rollout loops. A wave not selected remains lazy until selected. No-label/same-epoch plans reuse the exact cache.
3. Only successfully matched hit/collision model additions change hits.seq. Unmatched incoming callbacks, enemyHits count changes and visit-only additions do not independently trigger refresh. If multiple labels arrive before a plan, refresh once at the latest epoch. Cache epoch tracks sequence, not model size, including600-entry eviction. Original newRound clears active waves and own bullets but retains existing hits/visits learning as before.

The existing whole density estimator reads hits AND visits. A label-triggered refresh consequently also incorporates visits learned since that wave's previous computation. This is explicitly a full-estimator timing intervention, not a claim of an isolated hit-only effect. Do not split/reweight the estimator, add priors/features, change matching/removal, refresh merely on visits, or substitute current motion for immutable fire-time features. No Brace RAM correction, Helm STOP heading treatment, gun/request/fire-epoch redesign, fire policy/power/constants, radar, movement options, physics or shadow enablement. Candidate identity/launch files and bounded diagnostics/test seam are the only other changes; immutable original Keel and production AISurvivor stay byte-identical.

Legal information is our already-delivered own bullet-hit/collision event plus legal history. A bullet's true heading remains fixed; this updates our current posterior, not what the enemy could have known when it fired. It can hurt under nonstationary targeting or wave misassociation. No measured exposure or competitive benefit is established by the source audit. Fire economy deliberately remains unchanged; prior trained-prior, Helm and shadow experiments are not repeated.
